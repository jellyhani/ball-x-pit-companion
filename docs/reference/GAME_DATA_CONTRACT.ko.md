# 게임 정보와 계산의 대조 상태

대상: BALL x PIT 1.301 / 도우미 0.1.0-beta.1 / 연동 1.18.0.
이 문서는 계산의 근거와 남은 한계를 구분한다. 실제 게임에서 모든 결과가 일치한다는 인증은 아니다.
게임에서 읽은 코드·카탈로그·세이브·아이콘은 배포하지 않는다.

## 읽기와 적용 경로

| 항목 | 게임의 기준 | 도우미의 적용 | 검증 경계 |
|---|---|---|---|
| 반사 | `BaseMgr.MoveBalls`의 Raycast 법선과 정규화 | Python/C++ 내적 반사, 점 광선 | 원·경사면·벽 합성 검사. 실제 발사 대조 필요 |
| 벽·도로 | 활성 충돌체 Transform, 도로 타일 | 정적 벽 모양, 도로 진입·이탈 속도 | 지원하지 않는 벽은 계산 보류 |
| 발사 허용 | `BallPreview.IsInputEnabled` | 현재 방향과 함께 확인 후 경로 표시 | 허용 미확인·방향 불일치 시 표시 보류 |
| 참가자·발사 순서 | `BaseMgr.ActiveWorkers`, 발사 간격 상수 | 조준 중 게임의 목록·순서 우선 | 일반 기지에서는 참가 조건으로 예상 |
| 자원/건물 관통 | 실제 자원 분류, 충돌 계층, `WorkerHitBuilding` 호출 순서 | 접촉·채집·반사를 분리 | 관통해도 건물 접촉 처리. 빈 자원은 비활성 |
| 채집 범위 | Pickup 계층의 OverlapCircle | 밀 원형 범위, 모서리는 둥근 확장 영역 | 연속 이동 근사라 프레임별 접촉과 차이 가능 |
| 속도 | 현재 기본 속도·캐릭터 보너스, 반사당 +0.2, 상한 100 | 현재 getter 값과 상한 적용 | 캐릭터 보너스 자료가 없으면 명시적 제한 |
| 타격 효과 | `BuildingInst.GetHitByWorker` | 유령의 집·수도원·벽돌집·추가 작업자 | 상태 변화는 Python 계산 사용 |
| 공사 완료 | 공사 점수·목표, 완공 효과·용량 | 진행 점수 제한, 상태 변화, 이후 발사 속도 | 완공 후 작업 주기 등 일부 변화는 미검증 |
| 자동 생산·재생 | `WorldTimeMgr`, `AddTaskSecs`, 현재 작업 시계 | 시간순 재고 공유, 자동 생산 수입 별도 | 프레임 순서·캐시된 시계는 근사 |
| 효과 범위 | `BuildingUtl.IsInRange`, 회전한 대상 영역 | 대상 상자·회전 셀 겹침 | 현재 배치는 게임 대상별 판정과 독립 대조 |
| 건설 가능 수량 | 게임 추가 건설 목록·최대 개수 | 기존 개수를 빼고 구매 추천 제한 | 해금·비용·공사 중 여부도 별도로 검사 |
| 일꾼 생산 속도 | `GetTaskTgtSecs`의 건물별 분기 | 현재 자동 생산과 구형 시설용 강화를 구분 | 자동 농장·야적장·채석장은 건물 레벨 기준 |
| 전투 카드 수치 | `UpgradeInfo.GetPropertyByLvl` | 현재 런의 비복합 후보 before/after 적용 | 복합 볼은 일반 getter로 확정하지 않음 |
| 추천 점수 | 실제 수치 + 조합 진행 + 공략 평가 | 이유·대안·제한을 표시 | 미래 DPS의 정확한 시뮬레이션이 아님 |

## 자동으로 잡는 불일치

- 현재 배치의 대상별 포함 여부를 게임의 `IsInRange` 결과와 비교한다. 동일 결과를 자기 자신과 비교하지 않는다.
- 불일치가 있으면 이동·신규 건설 위치 계산을 보류하고 로컬 진단을 남긴다.
- 관측 당시 위치에서 이동하거나 회전한 후보는 과거 포함 목록을 재사용하지 않는다.
- 새 연동에서 모양을 읽지 못한 것을 구형 중심 거리 계산으로 숨기지 않는다.
- 발사 입력은 관측 시점의 팀·자원·세계 시계와 함께 복사한다. 다른 시점의 자료로 과거 결과를 설명하지 않는다.
- 범위 검사와 합성 물리 검사를 통과해도 실제 게임 일치 여부는 별도의 플레이 기록으로 확인한다.

## 아직 남은 한계

1. 매 프레임의 충돌/OverlapCircle 순서, 극단적인 모서리·동시 접촉, 런타임 추가 충돌체는 실측이 필요하다.
2. 자동 생산 시계가 매 초 바뀌면서 각도 탐색 결과를 계속 버리는 일을 피하려고 10초 단위로 각도 캐시를 갱신한다.
   현재 조준은 새 계산 요청 때의 시계를 사용하지만, 캐시된 추천에는 시차가 있을 수 있다.
3. 완공 이후 모든 건물의 전역 효과·작업 주기 변화, 자동 발사대·일부 자동 작업, 금광 난수 수입은 완전 모델이 아니다.
4. 직접 날린 작업자의 수확량과 자동 생산 수입은 구분한다. 전후 보유량 차이만으로 수동 수확 예측의 정확도를 판정하면 안 된다.
5. 카탈로그의 모든 수치 키를 읽었다는 사실은 모든 전투 효과를 계산했다는 뜻이 아니다. 복합 볼의 실효 수치와 미래 DPS는 미완성 영역이다.
6. 과거 발사 기록 중 효과·도로·세계 시계가 없는 자료는 정확한 수확량 재현 검사의 정답으로 사용하지 않는다.
7. 16개 언어의 키·자리표시자 검사와 화면 렌더링은 번역의 원어민 검수를 대신하지 않는다.

## 재현과 배포 확인

검증은 기본 계산 전체 검사, `BXP_NO_NATIVE=1` 전체 검사, 추천 회귀, 플러그인 빌드,
별도 프로필의 패키지 실행 검사, 실제 게임 수신 확인으로 나눈다.
패키지 검사는 합성 파이프와 별도 데이터 폴더를 사용한다. 사용자 게임을 조작하지 않는다.
게임 입력과 세이브 변경은 도우미의 기능에 포함하지 않는다.
